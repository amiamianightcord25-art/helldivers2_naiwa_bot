# QQ 原生自定义菜单与指令面板核验（2026-09-19）

本次直接读取腾讯官方现行公开文档（菜单/面板页更新时间 2026-08-13，API 指南更新时间 2026-09-17）。用户截图是客户端原生指令面板，不能用消息内 InlineKeyboard 冒称已配置截图入口。

## 结论与场景

官方已经提供公开 HTTP API，可以通过现有机器人 AppID / AppSecret 获取 access_token 后配置，不要求操作控制台完成每一次菜单/面板修改。实际应用是否具备接口权限以线上 API 响应为准。

| 场景 | 原生底部自定义菜单 | 原生指令面板 | 定向面板 |
| --- | --- | --- | --- |
| 普通 QQ 单聊 c2c | 支持，全局 | 支持 | 指定 user_openids |
| QQ 群聊 group | 官方未支持 | 支持 | 指定 group_openids |
| 文字子频道 channel | 官方未支持 | 支持 | 仅 target_type=all |
| 频道私信 dm | 官方未支持 | 支持 | 仅 target_type=all |

总览：[自定义菜单与指令面板](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/menu-panel/)

官方原文：“机器人可在单聊场景下配置自定义菜单，在单聊、群聊、文字子频道、频道私信场景下配置指令面板”。“自定义菜单展示在机器人单聊窗口底部……设置后对所有用户生效。”

## 精确 API

统一地址：[API 调用指南](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/api-call-guide.html) 指定 `https://api.bot.qq.com`。Header 为 `Authorization: QQBot {ACCESS_TOKEN}`。

获取 token：[获取访问凭证](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/access-token.html)

```http
POST https://api.bot.qq.com/app/getAppAccessToken
Content-Type: application/json

{"appId":"APPID","clientSecret":"CLIENTSECRET"}
```

成功字段 `access_token`、`expires_in`。token 接口失败也可能 HTTP 200，应检查 `code`；普通 API 应检查 `err_code`（兼容旧 `code`）。仅在进程内保存 token，不写入配置、计划或日志。

菜单修改会**覆盖整个菜单**，不是增量：

```json
{
  "menu": {
    "items": [
      {"name": "签到", "type": "send_message", "send_message": "签到"},
      {"name": "战情", "type": "menu", "sub_menu_items": [
        {"name": "战略看板", "type": "send_message", "send_message": "看板"},
        {"name": "DSS票数", "type": "send_message", "send_message": "DSS票数"}
      ]}
    ]
  }
}
```

返回 `{"version":1}`。`GET /v2/menu` 返回 `{menu,version}`；未设置过时 menu 为空。一级最多 10 项；一级名称最多 10 字符（中文计 2，即 5 个汉字）；子菜单最多 5 项，不可再嵌套，名称最多 14 字符（7 个汉字）。菜单类型 `switch/send_message/link/menu`，子菜单仅 `send_message/link`。链接必须 HTTPS。`send_message` 是填入用户输入框，官方没有承诺立即发送。

原生面板创建：

```json
{
  "scope": "group",
  "target_type": "all",
  "panel": {
    "remark": "hd2bot:group",
    "items": [
      {"type": "command", "name": "签到", "desc": "每日签到获得经验"},
      {"type": "command", "name": "战备英雄", "desc": "开始随机箭头挑战"}
    ]
  }
}
```

同一份结构分别用 `scope=c2c/group/channel/dm` 创建。返回 `{panel_id}`。一个机器人最多 20 个指令面板，一个面板最多 20 个元素。`command.name` 是点击后填入输入框的文字，不支持把展示名称与发送文本拆成两个独立字段；`link.name` 仅用于展示。名称最多 14 字符（约 7 个汉字），描述最多 30 字符（约 15 个汉字），remark 最多 255 字符，不向用户展示。`only_admin` 为布尔值，可限制群/频道管理员点击。面板中填不填 `/` 都应由业务解析兼容，官方示例使用 `查询天气`。

更新 body 只有 `{"panel":{"items":[...],"remark":"hd2bot:group"}}`；元素与备注整体替换，不改变 scope、target_type 或关联对象。列表返回 `records/next_cursor/is_end`；必须按 scope 查询，limit 默认 20、最大 50。cursor 为空或 is_end=true 则结束。

定向面板在创建时用 `target_type=specific` 加 `user_openids` 或 `group_openids`，一次最多 20 个；关联对象接口 body 为 `{"op":"add","group_openids":[...]}` 或 `op=del`。channel/dm 不支持此模式。本项目采用四场景全局面板，无需收集用户或群 ID。

## 已安装适配器与实现建议

本地 nonebot-adapter-qq 1.7.2 没有 `/v2/menu`、`/v2/panels` 方法；不能直接假设 `bot.put_menu()` 存在。它有 `Bot.get_access_token()`、`Bot.get_authorization_header()`、内部 `_request`，以及 MessageKeyboard / InlineKeyboard / Button / RenderData / Action 模型；消息发送支持 keyboard 字段。当前适配器默认 host 是 api.sgroup.qq.com，原生配置工具应依据新文档使用 api.bot.qq.com，保持应用业务适配器不受影响。

可执行方案：独立 aiohttp 客户端读取 Settings.load() 的 AppID/AppSecret，内存获取 token，先只读拉取菜单和四场景面板；产生配置差异；只创建或修改 remark=`hd2bot:{scope}` 的面板；不删除已有无关面板。重复运行无差异即不调用写接口。菜单默认合并保留既有无关顶级项；如果完整替换，必须在计划中显示旧值与新值。超过官方 10 项限制应报错，不截断旧菜单。

消息内菜单可作为用户主动发 `菜单` 后的补充体验；支持 Markdown 权限时用消息 keyboard，按钮 `action.type=2` 填入命令；若平台明确拒绝 Markdown / keyboard 则回退纯文本命令列表。发送超时不能立即补发，以免产生两份回复。它与原生菜单/指令面板是三个不同入口。

旧 SDK 按钮文档：[InlineKeyboard](https://bot.q.qq.com/wiki/develop/pythonsdk/model/inline_keyboard.html)、[带按钮消息](https://bot.q.qq.com/wiki/develop/pythonsdk/api/message/post_keyboard_message.html)，该旧页明确：“仅 markdown 消息支持消息按钮。”最多 5 行、每行最多 5 按钮。旧页 2022 年更新，实际消息字段和权限应以现行 API-v2 页面与返回值为准。
